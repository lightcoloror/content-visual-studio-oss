# Content Studio 字号硬门禁接入说明

## 意图

让社交卡片和文章 HTML 的字号要求从“渲染后人工看一眼”的建议，变成候选产物进入 QA 前必须通过的机器门禁。

## 决策

Content Studio 不维护第二份字号表。`social-card` 与 `html-playwright` 直接绑定 MVP Video 的权威策略文件：

`<mvp-video-pipeline-root>/src/video_creation_pipeline/policies/typography-gates.v1.json`

`social-card` 使用 `social_card_1080x1440`；文章 HTML 同时使用 `article_html_desktop` 与 `article_html_mobile`。绑定包括策略绝对路径、SHA-256、profile 和浏览器实际计算得到的每个文本节点字号。策略缺失、SHA 漂移、未知角色、无字号证据、低于角色下限或裁切溢出，都会使 `font-size-gate` 失败；失败产物仍可留下结构化回执，但不能作为通过 QA 的候选。

## 理由

`minimum_font_px` 只能找出“最小的一个字”，无法判断它是可较小的署名还是不应缩小的主标题。角色化回执将 `data-font-role` 置于第一优先级，并对普通 HTML 标签提供保守后备映射；所有可见阅读文本都必须被归类，不能安全归类的 `div`、`span`、`button` 等直接文本节点会标记为 `unclassified-reading-node` 并失败。每个节点都记录角色、来源、实际字号、边界框、溢出和角色阈值。

## 证据

- `lucas-case-cover-craft/references/platform-and-qa.md` 的手机小图一秒/三秒可读性门槛。
- `fixtures/typography-gate/` 的纯合成正例、低字号、未知阅读节点、缺主标题与策略哈希漂移反例。
- `tests/test_social_card_typography_gate.py` 与 `tests/test_article_typography_gate.py`：同一 collector 的社交卡片和文章双视口回归。

## 生效范围

当前对 Content Studio 的 `social-card` HTML/PNG 与 `html-playwright` 文章 HTML 生效。文章沿用既有 Puppeteer 浏览器 QA，只接入共享的策略加载器与角色 collector；双视口结果写入原有浏览器 QA 报告和 render receipt，不另建状态机或复制验证器。其他未接入的渲染器不得因此声称通过字号门禁。

## 回执字段

`render-receipt.v1.font_gate` 包含 `policy_id`、`profile_id`、策略路径和哈希、可见文本节点、节点边界框、实际字号、角色阈值、溢出、失败原因和 `passed`。文章记录 desktop/mobile 两组同类结果。
